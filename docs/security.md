# 脅威モデルと設計判断

## 守れるもの

| 攻撃者 | できないこと |
| --- | --- |
| サーバー運営者 / ホスティング事業者 | 平文・ファイル名・MIME タイプの復元（鍵を持たない） |
| DB / R2 のダンプを入手した者 | 同上。トークンも SHA-256 でしか保存されていない |
| 通信経路の傍受者 | TLS 1.3 に加え、中身は端末で暗号化済み |
| URL を推測しようとする者 | トークンは 256 bit。総当たりは非現実的 |
| リンクだけを入手した者（パスワード付きの場合） | 復号（Argon2id 由来の鍵が KEK に混ざる） |
| リンクを入手した者が回数を食い潰す（パスワード付き） | サーバーが `pwVerifier` を検証してから回数を消費する |

## 守れないもの（明示）

- **リンクの漏洩**（パスワードなしの場合）。`#` 以降を知っていれば誰でも復号できます。
  チャットやメールにそのまま貼ると、その履歴を読める全員がアクセスできます。
- **端末の侵害**。ブラウザ内で平文と鍵を扱うため、端末が乗っ取られていれば無力です。
- **配信サーバーの改竄**。JavaScript を配っているのはこのサーバー自身なので、
  サーバーが悪意を持てば鍵を盗む JS を配れます（Web における E2E 暗号の一般的な限界）。
  緩和策として CSP を `default-src 'self'` に絞り、外部 CDN を一切使っていません。
- **メタデータ**。暗号文のサイズ、ファイル数、アップロード日時、
  ダウンロード時刻・回数、アクセス元 IP は Cloudflare 側に残ります。
- **送信者の端末に残る履歴**。送信履歴（復号鍵を含むリンク）は localStorage に
  保存されます。共有端末では設定からオフにするか、履歴を消してください。
- **ウイルススキャン**。中身が見えないため、原理的に実施できません。

## 設計上の判断

### なぜ鍵を URL フラグメントに置くのか

フラグメントは HTTP リクエストに含まれず、`Referer` にも載りません
（さらに `Referrer-Policy: no-referrer` を送っています）。
サーバーが鍵を「見ないようにしている」のではなく、**構造的に受け取れない** ようにしています。

### なぜファイルごとに CEK を分けるのか

1 リンクに複数ファイルを入れるとき、同じ CEK を使い回すと
ファイル間で nonce が衝突する可能性が残ります（nonce のランダム部分は 4 バイト）。
ファイルごとに CEK を作り、共通の KEK でラップすることでこれを構造的に排除しています。
KEK はバンドルに 1 つなので、Argon2id の計算は何ファイルあっても 1 回だけです。

### なぜチャンクごとに AES-GCM なのか

- ファイル全体を 1 回の GCM で処理すると、復号前に全体をメモリに載せる必要があります。
- チャンクごとなら、上から順に検証しながらストリーム保存できます。
- チャンク番号と総チャンク数を AAD に束縛しているため、
  **並べ替え・切り詰め・チャンクの差し替え** はすべて検知されます。

### なぜ authToken が必要なのか

トークン（URL のパス）はサーバーのログやプロキシに残り得ます。
`authToken`（= リンク秘密由来、サーバーは SHA-256 のみ保持）を別途要求することで、
**ログを読めるだけの相手ではメタデータ API を叩けない** ようにしています。

### なぜダウンロード回数を「グラント」で数えるのか

100 GiB のダウンロードが途中で切れるたびに回数が減るのは実用的ではありません。
claim 時に 1 回消費し、12 時間有効な HMAC 署名付きグラントを返します。
その間は同じ回数のまま Range 取得・再開ができます。

### 回数到達後もすぐ消えるのはなぜか

claim で「アクティブなダウンロード数」を増やし、受信ページの完了通知 (finish) で
減らします。回数上限に達し、かつアクティブが 0 になった瞬間にサーバーは
R2 と D1 から完全削除します。タブを閉じても `sendBeacon` で通知が届きます。
通知が来ないクラッシュ等に備え、ダウンロード中は毎分の生存信号 (ping) を送り、
途絶から一定の猶予（既定 15 分）で Cron が削除します。
上限到達の時点で `/info` `/claim` は 410 を返すため、リンク自体は即時に無効です。
finish / ping はグラント（= 正当にダウンロード権を得た証明）が無いと呼べないため、
第三者が削除を早めることはできません。

### Argon2id のパラメータ

`m=64 MiB, t=3, p=1`（OWASP の推奨値）。ブラウザで 0.5〜1.5 秒程度かかります。
パラメータはファイルごとに保存しているので、将来強くしても古いリンクは開けます。

## 報告

脆弱性を見つけた場合は、公開 Issue ではなくリポジトリ管理者へ直接連絡してください。
